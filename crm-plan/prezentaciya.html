Проблема

«Битое планирование» и дырявая воронка

Слабый execution

Нет требовательности и дожима, либо нет людей под масштаб. Лечится ручкой требовательности и наймом.

Битое планирование ~60% игнорируют

Не умеем считать деньги и складывать декомпозицию. Итог — деморализация: ожидания ≠ реальность.

  • План «с потолка», воронка-болото, сделки теряются между этапами
  • Перелидоз — тоже битый план: лидов больше ёмкости → сливаем 30%

Проектирование воронки · принцип 1

Этап = результат, у каждого — ЦКП

✗ Как не надо

«Звоним» · «Думает» · «В работе» · «Переговоры»

действие/болото — не измеряется

✓ Как надо

«Квалифицирован» · «Встреча проведена» · «КП отправлено» · «Оплачено»

состояние в прошедшем времени = наблюдаемый результат

ЦКП этапа (ценный конечный продукт) — конкретный результат, без которого сделка не имеет права двигаться дальше. Пример: ЦКП «Встреча проведена» = снято ТЗ + зафиксирован следующий шаг.
Практикум A-Players
Проектирование воронки · принцип 2

Детализируй ключевые переходы —
иначе не увидишь потери

Одно событие → три этапа. Так замеряешь конверсию в запись и доходимость (no-show).

Встреча назначена → 100%
Явка · клиент пришёл → 80%
Встреча проведена → 80%
Было «Встреча» одним этапом — теряли 20% на неявке и не знали. Стало видно → чиним напоминания и подтверждение слота. То же для оплаты: «Счёт выставлен → Оплачено».

Проектирование воронки · принцип 3

SLA на этапах и целевые конверсии

  • SLA первого контакта — минуты, ≤5 мин (скорость ответа = конверсия)
  • Дальше SLA растёт по этапу: квалификация — часы, КП — дни
  • Превышение SLA = сигнал → сделка на дожим
  • У каждого перехода — целевая конверсия (бенчмарк ниши)

Пример · B2B, цикл 6–10 мес

ПереходSLAЦель
Лид → квалиф.≤5 мин80%
Квалиф. → встреча2 дня55%
Встреча → КП3 дня65%
КП → договор10 дней45%

Анализ по потенциалу · KAM

Share of wallet: сколько даёт vs сколько мог бы

  • Для B2B/KAM: у клиента есть потенциал — весь его бюджет на нашу категорию
  • Мы занимаем долю (share of wallet). Остальное — у конкурентов
  • Приоритет: клиенты с высоким потенциалом и низким текущим охватом
  • Это главный upside — растём внутри существующих

Пример

Завод берёт у нас на 3 млн/год, а бюджет на категорию — 12 млн. Охват 25% → цель KAM: 60%.

Никогда не считаем план одним методом

Один метод = иллюзия. Считаем минимум двумя, сверяем, и только потом берём в работу.

Метод 2 · Снизу-вверх (из pipeline)

Категории прогноза — по критериям

КатегорияКритерийВероятностьКак считаем
Committedподписан договор / внесена оплата100%берём полностью
Forecastвысокая уверенность (ЛПР «за», КП согласовано)> 85%× вероятность
Upsideсредняя вероятность≥ 60%× вероятность
Снизу-вверх = Committed + Forecast×вер. + Upside×вер. + база + проекты. Это честная цифра «что реально принесём». Для B2B деньги месяца = сделки, открытые 6–10 мес назад.

Метод 3 · От ёмкости команды

Потолок = min(люди, трафик)

Узкое место — люди

лидов хватает, но команда физически не отработает в качестве → нанимать

Узкое место — трафик

команда недозагружена → чинить лидогенерацию, а не давить на продавцов

Предохранитель сверху: план не может быть выше того, что команда отработает в качестве. Показывает, куда вкладывать для роста — в людей или в трафик.

Практикум A-Players
Синхронизация маркетинг ↔ продажи

Лидов должно хватать — но не больше ёмкости

  • Медиаплан: бюджет → CPL → лиды → сделки → выручка → ROMI
  • Лидов медиаплана должно хватать на цель по новому бизнесу
  • Но не превышать ёмкость продаж → анти-перелидоз
  • Расхождение — повод для факторного анализа, а не «зальём ещё»

Перелидоз = потеря денег

Лидов больше, чем команда отработает → сольём 30% и испортим базу. Сначала «приближаем эффект», иначе режем бюджет.
